## Elevator Pitch (<=250 words)
Blocnet is a crypto intelligence and execution product that helps users act on high-value on-chain opportunities before they expire. We convert fragmented updates from project ecosystems into structured, ranked, and actionable flows, then connect those flows to real wallet actions.

Our MVP is built and deployed, with core capabilities across project intelligence, decision support, wallet flows, and token participation mechanics. The next major step is adding decentralized, event-driven automation so critical actions can execute predictably across contracts and chains without relying on centralized job runners.

Reactive Network is a strong fit for this phase. We plan to implement Reactive Smart Contracts to power if-this-then-that automations for campaign lifecycle actions, time-sensitive participation windows, reward distribution logic, and cross-chain event-triggered workflows. This reduces operational bottlenecks, shortens response time to ecosystem events, and improves reliability of user-facing actions.

With Reactive support, Blocnet will ship production-grade decentralized automation primitives that benefit our users directly and can be reused by partner projects integrating through our platform.

## What key problem(s) your project is working to solve
1. Critical project actions are buried in noisy channels, causing users to miss time-sensitive opportunities.
2. Current automation in Web3 products often depends on centralized off-chain workers.
3. Cross-contract and cross-chain workflows are difficult to coordinate reliably in production.

Blocnet addresses these by combining structured intelligence with automated execution pathways so users can move from discovery to on-chain action with less friction and higher reliability.

## Please elaborate on how you are going to utilize the Reactive Network and Reactive Smart Contracts.
We will integrate Reactive Smart Contracts as the decentralized automation layer for Blocnet.

Planned implementations:
1. Campaign and update automation:
- If a tracked contract emits a campaign/action event (for example, claim window opened or governance action started), Reactive triggers downstream action contracts that register and route the opportunity in Blocnet with deterministic logic.

2. Time-sensitive participation rules:
- If deadlines, thresholds, or state transitions are met, Reactive executes pre-defined contract actions to update campaign states, enforce expiry handling, and prevent stale user actions.

3. Reward and incentive workflows:
- If participation conditions are satisfied on-chain, Reactive triggers reward-state updates and distribution pipelines through on-chain hooks.

4. Cross-chain reactive workflows:
- If an event is emitted on one supported chain, Reactive can trigger corresponding actions on another chain-facing workflow, reducing manual bridge-like coordination overhead.

This creates a decentralized execution path for core product automations that are currently painful to maintain with centralized workers.

## What problems / bottlenecks / challenges would it solve? Why is this important?
Reactive integration solves:
1. Centralized scheduler risk for critical automations.
2. Latency and reliability issues in off-chain event-processing pipelines.
3. Complex multi-contract workflow orchestration.
4. Operational burden of custom automation infrastructure.

Why this matters:
- Our product depends on timely execution. Missed or delayed automations directly reduce user trust and ecosystem participation. A decentralized event-driven execution layer improves correctness, uptime posture, and scalability for core user actions.

## Have you considered any other solutions to solve those problems? If so why is Reactive better?
Yes. We evaluated centralized worker/queue systems, custom indexers with cron-based automations, and keeper-like patterns.

Why Reactive is better for our use case:
1. Native event-driven execution model aligned with if-this-then-that product logic.
2. Smart-contract-level automation composability instead of bespoke centralized orchestration.
3. Better decentralization posture for user-critical execution flows.
4. Faster path to shipping production reactive workflows without rebuilding execution infrastructure from scratch.
