Overview

Status meanings: live reachable and working with real data · partial reachable but stubbed, empty by design, mis-gated or visibly incomplete · dead code exists but nothing reaches it · unverified exists in code, could not be exercised this session.

44Mobile routes39 protected + 5 auth · 4 dead routes
36Console pages34 in nav · 1 deep-link only · 3 public
~180Backend endpoints34 feature modules · 71 Prisma models
8Server capabilities with no clientplus 1 broken client→server path

Headline. The product is broad and mostly real: the three mobile spaces, the whole console nav, and the economy stack (wallet, tips, mining, quests, badges, levels) all render live data. The gaps cluster in four places: hunter onboarding (Become Hunter, project assignment invites) is built on the server but unreachable on any client; KYC has a full admin review queue but no way for a user to submit; the console member-detail page is half placeholder; and several mobile entry points lead to "coming soon" or a role error.

UX/UI findings, prioritized

Judged as a first-time user, not a bug hunt. P1 = blocks or misleads a new user on a main path · P2 = confusing or inconsistent, worth a design decision · P3 = polish. Each item names the surface and the screen or file so it can be picked up cold.

P1 · fix before anyone else signs up

  1. F-01
    The "space" concept is invisible until you stumble on itmobilenavigation
    The only entry to User / Hunter / Moderation is an unlabeled logo icon in the app bar. Switching re-skins the whole app (accent color, tab 2, the entire Profile body) with a blackout transition, and the Hunter-space Profile hides Badges, Quests, Levels and Activity that the User-space Profile shows. A new hunter will think features disappeared. Decide: either make spaces an explicit, named control with an onboarding moment, or collapse to one shell with role-aware sections.
    app_bar.dart space switcher · main_screen_shells.part.dart · user_profile_body.dart vs hunter_profile_body.dart
  2. F-02
    Raw exception strings shown to usersmobileerror copy
    Hunter Hub rendered "Tip sync warning: ClientException: Connection closed before full header was received, uri=http://localhost:3080/api/tips/history?limit=100…" inside two cards, in orange, with a "Retry Sync" button. Internal URLs and Dart class names leak on a transient network hiccup. Profile shows "Insufficient role permissions" in a red banner when an admin taps the System Alerts entry the menu itself offered.
    hunter_hub_screen.dart tip sections · system_alerts_screen.dart · user/hunter profile bodies (System Alerts row gated owner/dev/admin, API allows owner/dev)
  3. F-03
    Referral screen looks broken: totals are "…" forevermobiledata
    Total Referrals and Active Referrals never resolve because no client calls /referrals/me. The code and copy buttons work, so the user assumes the counts are loading. One fetch fixes it; until then show "0" or hide the tiles.
    referral_code_screen.dart · mining_store.dart
  4. F-04
    Layout jumps sideways when a menu or tab opensconsolelayout bug
    Opening the row "…" menu on Projects, or switching tabs on a member detail page, scrolls the whole viewport horizontally so the sidebar slides half off-screen. The shell is h-screen overflow-hidden, but the content column still has a wider-than-viewport child (likely the fixed "Stage" badge or a table min-width) that Radix focus-scroll reveals. It happens at 1372px, so it is not a narrow-screen issue.
    components/admin-shell/index.tsx · features/users/[id] tab bar · any page with a DropdownMenu
  5. F-05
    Member detail is half placeholder and mislabels the memberconsoleincomplete surface
    Header reads "Unnamed User" for claude-audit because display name is empty; it should fall back to username. Of seven tabs, Activity, Social and System are "will be available here", Projects tiles are hard-coded "—", and Lifecycle notifications are a stub. An admin landing here from Members reads the page as broken rather than unfinished. Either ship the sections or hide the tabs until they exist.
    features/users/[id]/components/{ActivitySection,ProjectsSection,SocialSection,AuditLogSection,LifecycleSection}.tsx
  6. F-06
    Wallet quick actions do not do what they saymobileaffordance
    "Receive" opens the BNT asset detail page (which has its own Receive button) instead of an address / QR view; the address only lives on the wallet home. "Swap" opens a list titled "Swap flow is in rollout" with no conversion step. Both are first-tap actions on a money screen and both dead-end. Also note "Pre-launch" is set as the balance at hero size with no inline explanation of what that means.
    wallet/presentation/widgets/quick_actions.dart · swap_flow_screen.dart · wallet_screen.dart hero

P2 · confusing or inconsistent, decide together

  1. F-07
    Vocabulary differs between surfacescross-surfaceconsistency
    Mobile says Gems, Submit New Gem, Hunter updates, Users; console says Projects, Project Proposals, Updates, Members. Mobile mines BNP and tips in BNP while the wallet holds BNT; the console tip settings add MCR. Nothing on either surface explains BNP vs BNT. A one-page glossary and a rename pass would remove most support questions.
    mobile profile menus, discover, hunter hub · console Sidebar.tsx, tip-settings

    Cold start shows a half-built home for ~7 smobileperceived performance

  3. F-09

  7. F-13

Set a type scale in the theme (minimum 12 for anything readable, 13–14 body) and replace the literals.

Method

Three code-inventory passes (router + stores, console pages + nav + hooks, backend controllers + schema + client grep) ran in parallel, then every reachable screen was opened live: 116 emulator screenshots via adb across all three spaces, and every console page plus its dialogs in Chrome at desktop and tablet widths. Status is "live" only when I saw it render real data. Findings were written from the screenshots, then cross-checked against the code so each names a file.
